# Policy Test

[ADR-0402](../../docs/adr/0402-policy-test-scope-and-verification.md) の Policy 層である。本リポジトリの ADR を読まなければ書けない invariant だけを持つ（同 決定1-3）。`make tf-policy` が実行し、`make tf-policy-canary` がその検査自体を検査する（[`.makefiles/terraform/policy.mk`](../../.makefiles/terraform/policy.mk)）。

## 入力

各 `usecases/<use-case>/reference/tests/policy-input.tftest.hcl` を mock provider で plan し、`terraform test -json -verbose` が出す `test_plan` から `provider_schemas` を除いたものである（同 決定11）。すべての reference の root がこのファイルを持たなければ、`make tf-policy` は落ちる。

policy の文書が参照する ARN は、`override_resource`（`override_during = plan`）で instance ごとに与える。与えないと文書が plan で unknown になり、`[PLAN-INPUT-04]` で落ちる。

`env/` の root は `make tf-policy` の入力にしない。資格情報なしでは plan できないためである。CI の plan と apply の経路（`.makefiles/terraform/operation/ci.mk` の `CI_PLAN` と `CI_APPLY`）は、実 provider の plan の `terraform show -json` に `plan.stateful_protection` だけを掛ける。ほかの package は mock の入力を前提にしているので、実 plan には掛けない。

入力は `tmp/tf-policy/` に書かれる。mock の値だけを含む。`make tf-policy` も CI の `tf-policy` job も、これを artifact や Pull Request のコメントへ出さない。

## 宣言

[`decl.json`](decl.json) が1箇所に持つ（同 決定15）。`make` は `--data` にこのファイルだけを渡す。

| キー | 中身 |
| --- | --- |
| `plan_format_version` | 読める入力の形の版。違えば `[PLAN-INPUT-02]` で落ちる |
| `resource_wildcard_actions` | identity-based policy の Allow で Resource `"*"` に与えてよい Action。AWS の Service Authorization Reference が resource-level 権限を持たないとする Action だけを置き、足す変更はその根拠を ADR に記録する（[ADR-0301](../../docs/adr/0301-least-privilege-policy.md) 決定9）。宣言が無ければ一覧は空として扱い、Resource `"*"` の Allow はすべて `[PLAN-IAM-03]` で落ちる。結合した入力のどの Resource `"*"` の Allow にも使われていない Action を置くと `[PLAN-IAM-06]` で落ちる |
| `documents` | policy の文書として読む resource の型と属性。表に無い型の文書は読まない。mock provider は表に無い computed な属性にも乱数を入れるので、属性の名前だけでは拾わない |
| `required_documents` | 入力のどこかに必ず現れる型。現れなければ `[PLAN-INPUT-07]` で落ちる。表から型が消えても黙らないための宣言 |
| `deployment_identity` | 信頼条件を見る role と OIDC provider の address（index key を除いた形）と、権限を見る plan の role と、その inline policy の address（`plan_role` の `role` と `policy`。apply 系の instance と分けるため index key 付き）と、plan の role に許す `logs:` の Action の一覧（`plan_role` の `logs_actions`。無ければ空として扱い、`logs:` の Action はすべて `[PLAN-ROLE-05]` で落ちる。配列でないとき、文字列でない要素や wildcard を含む要素を持つときは `[PLAN-ROLE-07]` で、規則が持つ閉じた集合（ログの event を返さない読み取り）の外の要素は `[PLAN-ROLE-08]` で、plan の role のどの Allow にも使われていない要素は `[PLAN-ROLE-06]` で落ちる）。宣言した role が入力に無ければ `[PLAN-TRUST-00]`、plan の role かその policy が無ければ `[PLAN-ROLE-00]` で落ちる。Deny を見る apply の role の inline policy の address（`apply_role` の `policy`。index key 付き）。無ければ `[PLAN-APPLY-00]` で落ちる。apply の role が Resource `"*"` の Deny で拒む、resource type を持たない Action の一覧（`apply_role` の `wildcard_denies`）。空なら `[PLAN-APPLY-00]` で落ちる。apply の role と apply-identity の role の address（`apply_role` の `role` と `apply_identity_role` の `role`。apply-identity の role は for_each の外の resource なので index key を持たない）。unlock-identity の role と inline policy の address と、それが外す lock file の key と、その lock file を置く state の Bucket の address（`unlock_role` の `role`・`policy`・`lock_key`・`state_bucket`）。無いか、role の名前・ARN か Bucket の ARN が plan で決まらなければ `[PLAN-UNLOCK-00]` で落ちる |
| `state_backend` | state Bucket・その Bucket Policy・state の鍵・その Key Policy の address（`bucket`・`bucket_policy`・`state_key`・`key_policy`）、root ごとの書き手と state の key（`roots`。`writer` は `deployment_identity` の項目名、`state` は lock file でない key で、lock file は `<state>.tflock`）、lock を外す role（`unlocker`。消せる key は `deployment_identity.unlock_role.lock_key`）、state の鍵の暗号操作を許す role（`key_user_roles`。`deployment_identity` の項目名）。role は名前ではなく address から ARN を引く（[ADR-0402](../../docs/adr/0402-policy-test-scope-and-verification.md) 決定13）。無いか、空か、形が違うか、同じ role を2つの役割に宣言するか、ARN が plan で決まらなければ `[PLAN-SBW-00]` で落ちる。workload root の apply の role を Key Policy に足す変更は `key_user_roles` を直す |
| `stateful_protection` | 削除と置換から守る resource の型（`protected_types`。`aws_s3_bucket` と `aws_s3_bucket_lifecycle_configuration` を必ず含む）と、root ごとの意図した削除と置換の許可（`allow`。root の名前をキーに、`address` と空でない `reason` の並び）。root ごとの意図した保持日数の短縮の許可（`shorten_allow`。同じ形。省けば空として読む）。root の名前は入力のファイル名から `.json` を除いたもの。形が崩れれば `[PLAN-STATE-00]` で落ちる |

宣言そのものが欠けたり形が違ったりすれば `[PLAN-DATA-01]` で落ちる。

## Policy を足すとき

- `<name>.rego` と `<name>_test.rego` を同じディレクトリに置く。規則は `deny contains` で書き、違反の ID（`[PLAN-<区分>-<番号>]`）を持たせる。テストは `test_violation_` と `test_pass_` で始まる名前の両方を持ち、各 ID をどこかのテストが名指しする（名指しの有無までを見る。違反側のテストが名指すかは見ない）。どれかが欠けると `make tf-policy` が落ちる（同 決定8・9）
- 見る resource の型と address は `decl.json` に足す
- Security の道具（[ADR-0501](../../docs/adr/0501-development-tooling-composition.md) 決定6）の既定のルールと重ならないことを、本リポジトリの書き方の文書で確かめる（ADR-0402 決定3）。確かめた結果は Pull Request に書く
