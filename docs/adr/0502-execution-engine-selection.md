# ADR-0502: 実行エンジンにTerraformを採用し、OpenTofuを採らない

- Status: Accepted
- Date: 2026-09-16
- Scope: repository-wide
- Related: ADR-0101, ADR-0205, ADR-0206, ADR-0501, ADR-0602

## Context

本リポジトリのADRは一貫して「Terraform」と書いてきたが、それは構成言語の総称としての用法であり、実行エンジンの選定としては記録されていない。ツールのversionを固定する manifest（ADR-0501 決定19）へ `terraform` と書いた時点で、リポジトリ最大の依存が記録なしに決まる。

選択肢は2つある。

- Terraform（HashiCorp、BUSL-1.1）
- OpenTofu（Linux Foundation、MPL-2.0。2023年のライセンス変更を契機とした fork）

**本リポジトリの運営方針として、選択肢が同等であればOSSを優先する姿勢がある。** この姿勢はこれまでどのADRにも記録されていない。エンジンの選定は、この姿勢と最も強く衝突する箇所である。結論だけを記録すると、姿勢を曲げた事実と、その代償として何を得たかが残らない。

また、判断の前提として広く語られる論点のうち、事実確認によって否定されたものがある。「OpenTofuはprovider の最新状況に追随していない」という前提は、調査時点では成立しない（決定11 の記録を参照）。

## Decision

### 採用

1. 実行エンジンをTerraformとする。調査時点の最新である 1.16.2 を pin の起点とする。
2. manifest が pin するのはCLIのversionであり、module が `required_version` で宣言するのは実際に使用する機能から導かれる検証済みの下限とする（ADR-0205 決定8）。両者を同一の値へ固定しない。CLIを更新するたびに全moduleの下限が上がる構造を作らない。

### 採らない理由

3. OpenTofuを採らない理由を、**ADR-0501 決定4 がStatic Analysisの権威に据えたTFLintが、OpenTofuを対象としないこと、ただ1点**とする。検査レイヤーの権威が1つ不在になることは、ADR-0101 決定3 が優先する対象（テスト可能性）に直接当たる。
4. 次を採否の理由としない。これらを理由として持ち出す再検討を認めない。

   - ライセンスの種別。BUSL-1.1 が制限するのは競合するサービスの提供であり、本リポジトリの利用形態は該当しない
   - 機能の数、およびどちらが先に実装したか
   - 採用シェア
   - 提供元の企業属性

5. TFLintの代替を自前で実装しない。tflint-ruleset-aws はAWS providerのschemaに追随して維持されるルール群であり、置き換えは一回性の作業ではなく、providerのリリースごとの追随義務になる。ADR-0501 決定2（Terraform CLIが提供する機能を外部ツールで再実装しない）および決定3（独自実装の3条件）に反する。
6. 「OpenTofu固有の構文を使わなければTFLintは動作する」ことを前提にしない。state暗号化は `terraform` block 内の構文であり、**OpenTofuを採る最大の理由を実際に使った時点で、Static Analysisの前提が崩れる**。検査の成立が、使う機能の選択に依存する構成を採らない。

### 捨てた姿勢の記録

7. 本決定は、選択肢が同等であればOSSを優先する運営方針に反する。衝突の内訳を次のとおり記録する。

   | 区分 | 内容 |
   | --- | --- |
   | 捨てたもの | OSI承認ライセンスのエンジンを用いること。エンジンの供給元が単一企業でないこと |
   | 捨てていないもの | 本リポジトリ自身のライセンス。エンジン以外の道具の選定方針 |
   | 引き換えに得たもの | Static Analysisレイヤーの権威（ADR-0501 決定4） |

8. 本決定を、他の道具の選定における先例としない。エンジン以外では、同等の機能を持つ選択肢が複数ある場合にOSSを優先する。
9. 選択肢が同等でない場合に、ライセンスを理由として検査レイヤーを欠いた構成を採らない。決定3 はこの一般則の適用結果である。

### 供給の独立性への備え

10. エンジン固有の機能への依存を最小化する。とくに、CLI単体では成立せずHCP Terraformを要する機能に依存しない（ADR-0501 案C で既に退けた範囲）。エンジンを切り替えた場合に失われる検査は、ADR-0501 決定4 の表として特定可能な状態を維持する。

### 調査の記録

11. 本決定の根拠として確認した事実を記録する（ADR-0206 決定8 と同じ形式）。

    - 調査日: 2026-09-16
    - Terraform 1.16.2（2026-09-09）/ OpenTofu 1.12.6（2026-08-19）
    - TFLint 0.64.0（2026-07-17）/ tflint-ruleset-aws 0.48.0（2026-06-29）
    - AWS provider: `registry.opentofu.org` と `registry.terraform.io` のいずれも最新は 6.64.0。stable の保持数は前者 513、後者 503
    - OpenTofu の linting に関する issue（opentofu/opentofu #2213、2024-11-22 起票）は open かつ pending-decision。`tofu lint` の一次実装、TFLint fork のいずれも着手されていない
    - TFLint のライセンスは MPL-2.0 だが、`terraform` package の一部は BUSL-1.1 であり、配布されるバイナリは両者に拘束される
    - Terraform 1.16.0（2026-08-26）で module 内の `import` block が正式にサポートされた（ADR-0602 決定6 の前提）

## 検討した代替案

### 案A: OpenTofuを採り、TFLintをTerraform互換構文の範囲で使い続ける

ライセンスの姿勢を保ったまま、Static Analysisも維持できるように見える。ただしOpenTofu固有の構文を使えなくなるため、state暗号化をはじめ、OpenTofuを選ぶ理由そのものを使えない。加えて、TFLintがどの構文まで受理するかは上流の都合で変化し、こちらからは制御できない。**検査の成立が、他者の実装都合に依存する構成になる。**

### 案B: OpenTofuを採り、Static Analysisを自前のPolicyで代替する

ライセンスの姿勢を保ち、固有機能も使える。ただしAWS providerのschemaに追随するルール群を継続的に維持する義務を負う。ADR-0501 決定2・決定3 に反し、ADR-0101 決定3 の優先順位（保守の労力をテスト可能性より上に置かない）とも整合しない。

### 案C: OpenTofuを採り、Static Analysisレイヤーを持たない

最も単純で、ライセンスの姿勢も保てる。ただしADR-0401 決定4 が定めた故障モードのうち、構文・書式の逸脱、deprecated設定、無効なProvider設定の検出手段が失われる。検出されなくなる故障モードを明示せずに層を削ることは、ADR-0401 決定17 が禁じている判断様式に当たる。

### 評価

| 評価軸 | 案A: 互換構文に限定 | 案B: 自前Policy | 案C: 層を持たない | 採用案: Terraform |
| --- | --- | --- | --- | --- |
| Security | 中 | 中（追随漏れが穴になる） | 低 | 高 |
| Testability | 中（上流都合で変動） | 中 | 低（層が欠落） | 高 |
| Contract Clarity | 中 | 中 | 中 | 高 |
| Scope Control | 中 | 低（実装資産が増え続ける） | 高 | 高 |
| Maintainability | 低（制御できない依存） | 低（継続的な追随義務） | 高 | 中 |
| License / 供給の独立性 | 高 | 高 | 高 | **低（意図的に捨てる）** |

評価軸「License / 供給の独立性」はADR-0101 決定6 の一覧に無い。同決定が各ADRによる軸の追加を許容しているため、本ADR限りの軸として加える。

## 意図的に捨てるもの

- OSI承認ライセンスの実行エンジンを用いること
- 実行エンジンの供給元が単一企業でないこと
- 供給元のライセンス方針の変更に対して、移行以外の防御手段を持つこと
- OpenTofu固有の機能（state の client-side 暗号化、provider の `for_each`、early variable evaluation、`-exclude`）

## 保証範囲

- 保証すること: ADR-0501 決定4 の全レイヤーが、選定したエンジンの上で成立すること。エンジンを切り替えた場合に失われる検査が特定可能であること
- 保証しないこと: 実行エンジンのライセンスが将来にわたって現在の条件を維持すること。OpenTofu固有機能と同等の機能が提供されること

## 検証方法

- Static Analysis: manifest に pin されたエンジンのversionが存在すること（ADR-0501 決定19）
- Static Analysis: 各moduleの `required_version` が、CLIの pin と同一値に固定されていないこと（決定2）
- Static Analysis: HCP Terraform を要する設定（`cloud` block 等）が存在しないこと（決定10）
- レビュー: 決定4 が列挙した理由による再検討の提起を差し戻すこと。機械判定できないため、本ADRの見直しを提案するPull Requestのレビュー観点とする

## 影響

- state の平文問題に対する防御は、KMSによる保存時暗号化とアクセス制御に限られる（ADR-0602）。client-side 暗号化という選択肢は本決定によって失われている。
- 本リポジトリのライセンス方針とエンジンのライセンスが一致しない状態が常態となる。テンプレートとして配布する際、採用側がこの差を認識できるようREADMEに記載する。
- 移行の余地を保つため、ADR-0501 決定4 の表がエンジン切り替え時の影響範囲の一覧を兼ねる。

## 見直し条件

- `tofu lint` の一次実装、またはTFLint相当のOpenTofu対応linterが実用水準に達した場合
- TFLintがOpenTofuの対応を表明した場合
- Terraformのライセンスが、本リポジトリの利用形態を制限する形へ変更された場合
- CLI単体ではADR-0501 決定4 の各層が成立せず、HCP Terraformを要する状態になった場合
- state の平文に起因する問題が、KMSとアクセス制御では閉じられない形で顕在化した場合
