# ADR-0504: 実AWSの資格情報を扱う道具をホストで実行する

- Status: Accepted
- Date: 2026-09-24
- Scope: repository-wide
- Related: ADR-0503, ADR-0602, ADR-0501, ADR-0301, ADR-0401

## Context

[ADR-0503](0503-tool-execution-form.md)（道具の宣言を1つに保ち、実行環境を3経路に分ける）決定4 は、道具の実行環境を表で分けた。その表の主語は、実行エンジン・単一の静的バイナリの検査ツール・パッケージエコシステムの install を要する道具・運用機構である。同ADRの Context 全体が「同じ検査が環境ごとに違う道具で走ると、CIと手元の食い違いを切り分けられない」という問題に向いており、表はその問題に答えるために引かれている。

このリポジトリには、その表のどの行にも当たらない道具がある。[ADR-0602](0602-bootstrap-and-ci-authentication.md)（bootstrapをCLIとimportで立ち上げ、CI認証をOIDCとする）決定4 の段1 が state backend の実体を作るために使う AWS CLI である。検査の道具ではなく、実行エンジンでもなく、運用機構でもない。**実環境を変更する道具であり、人が持つ AWS の資格情報を使う。**

表に行が無いことは、その道具について決定が無いことを意味する。実際 `.makefiles/host-tools.mk` がこの道具をホストへ導入したとき、その判断の根拠は `mise.toml` の当該宣言の直上のコメントにしか存在しなかった。**規則の持ち主はコメントではない**（[ADR-0701](0701-documentation-ownership-and-language.md) 決定1）。コメントは検査を持たず、宣言が動いても誰も更新を求めない。

判断を要するのは実行環境である。検査の道具と違い、この道具が読むのは資格情報であり、書くのは実環境である。**実行環境の選択は、その資格情報がどこを通るかの選択でもある。**

## Decision

1. 実 AWS の資格情報を用いて実環境を操作する道具を、手元ではホストで実行する。
2. 決定1 の道具を `.makefiles/host-tools.mk` がホストへ導入する。版の出所は [ADR-0501](0501-development-tooling-composition.md)（検証と運用の道具を既存ツールの組み合わせで構成する）決定19 の manifest とし、そこへ書き写した版を静的検査が守る。
3. 決定1 の理由を次の2つとする。

   - **人が持つ AWS の資格情報を、コンテナ境界越しに渡さない。** 渡すには環境変数・資格情報ファイルのマウント・credential process のいずれかを選ぶことになり、どれも資格情報の到達範囲を1つ広げる。広げた範囲は、道具を使い終えても縮まない。
   - bootstrap は、CI が実行できるようになる前に人が手元から進める手順である（ADR-0602 決定4 の段1から段4）。起動経路を短く保つことの価値が、経路を統一することの価値を上回る。

4. 決定1 に当たる道具として AWS CLI を置く（ADR-0602 決定4 の段1）。
5. 決定1 は実行環境についての決定であり、それ以上を含まない。ホストで実行することは、使う資格情報の権限を広げてよいことを意味しない —— ADR-0602 決定2 が bootstrap について [ADR-0301](0301-least-privilege-policy.md)（最小権限をdefaultとし、安全な設定をopt-inにしない）の免除を否定しているのと同じである。

### 本ADRで決定しない事項

6. **決定1 の道具がツールランナーのイメージに存在してよいかは、本ADRの対象外とする。** その主張を機械的に検査する手段を現時点で持たないためである（[ADR-0401](0401-testing-policy.md)（テストを第一級の設計要件とする）決定3）。検査を持たない主張を決定として述べると、守られているかどうかを誰も知らないまま規則だけが残る。

## 検討した代替案

### 案A: ツールランナーのイメージで実行する

検査の道具と同じ経路になり、手元の実行環境が1つ減る。ADR-0503 決定8 の「定義は1箇所」とも整合する。

ただし資格情報をコンテナ境界越しに渡す必要があり、そのための経路を新たに選ばなければならない。得られるのは起動経路の統一であって、**塞がる故障モードが無い** —— bootstrap の失敗は道具の版ではなく資格情報と権限に起因するもので、コンテナはそれを再現可能にしない。

### 案B: 実行環境を決めず、利用者に委ねる

決定を持たないため、どの環境でも動く。ただし利用者ごとに資格情報の通り道が変わり、bootstrap の手順書が「どこで実行するか」を書けなくなる。手順書が書けない手順は、[ADR-0601](0601-change-delivery-path.md)（変更経路をGitに限定し、applyをmerge後のCI/CDで行う）決定5 の例外として記録する対象（ADR-0602 決定10）を曖昧にする。

### 案C: ADR-0503 を supersede し、決定4 の表へ行を足す

分類が1つの表に集まり、読む場所が1つで済む。**ADR-0503 決定5 は既に資格情報の経路を理由の1つとして挙げている**（`terraform` について「OIDC による資格情報の受け渡しに、コンテナ境界を1つ増やすと経路が増える」）ため、資格情報を理由とする行がその表に在ること自体は新しくない。

採らない理由は主体の違いにある。決定5 が述べるのは **CI が OIDC で得る短命の資格情報**であり、本ADRが述べるのは**人が持つ長期の資格情報**である。前者は経路の数の問題だが、後者は到達範囲の問題であり、広がった範囲は道具を使い終えても縮まない。この2つを同じ表の行として並べると、行の根拠が読み手に区別できなくなる。加えて ADR-0503 の見直し条件（CIの実行環境の速度、npm / PyPI の道具の要否）は、この決定の見直し条件と一致しない。

### 評価

| 評価軸 | 案A: イメージで実行 | 案B: 委ねる | 案C: 0503をsupersede | 採用案: ホストで実行 |
| --- | --- | --- | --- | --- |
| Security | 低（資格情報の到達範囲が広がる） | 低（通り道が不定） | 高 | 高 |
| Testability | 中 | 低（前提を書けない） | 高 | 中（導入までを検査する） |
| Contract Clarity | 中 | 低 | 中（表が2つの理由を持つ） | 高 |
| Maintainability | 中 | 高 | 低（全参照の更新を伴う） | 高 |
| Scope Control | 中 | 低 | 中 | 高 |

## 意図的に捨てるもの

- 手元の実行環境が1つであること
- 検査の道具と同じ経路で bootstrap の道具を起動できること
- 「決定1 の道具がイメージに入っていないこと」を機械的に知れること（決定6）
- 道具の実行環境の分類が、単一の表から読み取れること

## 保証範囲

- 保証すること: 決定1 の道具が、manifest が宣言する版でホストへ導入されること。その版の写しが宣言からずれた状態で検査が通らないこと
- 保証しないこと: 決定1 の道具がツールランナーのイメージに存在しないこと。実行時に人がどの資格情報を使うか。導入された道具が実際にホストで実行されたこと

## 検証方法

以下を静的検査の対象とする（ADR-0401 の Static Analysis レイヤー）。

- `.makefiles/host-tools.mk` が決定1 の道具を導入する記述を持ち、その版が決定2 の manifest と一致すること。**一致件数を期待値と突き合わせるため、記述が消えた場合は「0件一致」として検査が落ちる** —— 対象を失ったまま成功で返らない（[ADR-0702](0702-repository-operations-substrate.md)（リポジトリ運用機構を独立した区分とし、Goで実装する）決定13）
- 決定6 のとおり、「イメージに存在しないこと」の検査は持たない。**この欠落は本ADRが明示的に引き受けたものであり、検査があるかのように読まれてはならない**

## 影響

- bootstrap の手順書は、決定1 の道具がホストに在ることを前提にしてよい。導入の入り口は `.makefiles/host-tools.mk` が提供する
- Docker が使えない環境でも bootstrap の段1 は実行できる。ADR-0503 決定5 が terraform について述べた性質が、この道具にも当てはまる
- ADR-0503 決定4 の表は変わらない。本ADRはその表が扱っていない類について述べるものであり、表の行を書き換えるものではない
- 決定1 に当たる道具が増えた場合、その都度、適用範囲の判断を伴う

## 見直し条件

- host / container の分類を突き合わせる検査が現れた場合。決定6 が対象外とした主張に、機械検査を与えられるようになる
- 資格情報の受け渡しが、コンテナ境界を越えても経路を増やさない形で標準化された場合
- 決定1 に当たる道具が2つ以上になり、個別の判断では扱えなくなった場合
- bootstrap が人の手元での実行を要しなくなった場合
