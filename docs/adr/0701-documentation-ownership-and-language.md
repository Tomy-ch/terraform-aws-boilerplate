# ADR-0701: 文書の所有と言語を定める

- Status: Accepted
- Date: 2026-09-16
- Scope: repository-wide
- Related: ADR-0001, ADR-0102, ADR-0206, ADR-0401, ADR-0501

## Context

本リポジトリには性質の異なる文書が同居する。

- ADR（設計判断の記録）
- AI コーディングエージェント向けの作業規約
- ユースケースの説明（supported / unsupported、公開契約）
- 公式実装の参照記録（ADR-0206 決定8）
- terraform-docs が生成する input / output の一覧（ADR-0501 決定25）

同じ規則が複数の文書へ写ると、片方だけが古くなる。読者はどちらが正かを判定できず、規則そのものが機能しなくなる。ADR-0001 は ADR の配置と所有を決めたが、ADR 以外の文書については決めていない。

言語も決まっていない。ADR は日本語で書かれている一方、リポジトリ直下には英語の規約文書とその日本語訳が併置されている。訳文の同期は機械検証できず、原文と訳文の乖離は読者からは見えない。乖離が security に関わる規則で起きた場合、片方だけを読んだ実装者は invariant を破る。

## Decision

### 所有

1. 1つの規則は1つの文書が所有する。他の文書はそれを参照し、再掲しない。
2. 所有の割当を次とする。

   | 対象 | 所有する文書 |
   | --- | --- |
   | 設計判断とその根拠 | ADR（配置は ADR-0001 に従う） |
   | AI コーディングエージェントの作業規約 | `AGENTS.md` |
   | ユースケースの責務境界・supported / unsupported | `modules/<use-case>/README.md`（ADR-0102 決定2） |
   | 公式実装の参照記録 | ADR-0206 決定8 が定める位置 |
   | module の input / output の一覧 | terraform-docs の生成区間 |
   | 開発の経緯・変更履歴 | git |

3. 文書本文に変更履歴と経緯を書かない。決定はその時点の形で書き、履歴は git が持つ。
4. 生成区間を編集しない。生成区間を持つ文書は、生成区間と人が書く区間を機械可読な境界（生成器が定めるマーカ）で分離する。
5. `AGENTS.md` はアーキテクチャ規則を再掲しない。エージェントが読む入口として、どの ADR が何を所有するかを指す。

### 言語

6. 文書の正本を日本語とする。
7. 同一内容の翻訳ペアを作らない。`*.ja.md` のような訳文ファイルを置かない。
8. 英語で書くものを次に限る。

   - HCL の識別子（block label、`variable` / `output` / `local` の名前）
   - ファイル名・ディレクトリ名
   - commit message の prefix
   - 技術用語（AWS のサービス名・API 名・コマンド名・HTTP status code 名等）

9. 散文を日本語で書く。対象は ADR 本文、`README.md`、`variable` / `output` の `description`、コードコメント、commit message の subject と body、Pull Request の title と body とする。
10. `terraform test` の `run` block label は HCL 識別子であり、決定8 に従い英語とする。そのテストが何を主張しているかの説明は、当該 block のコメントまたは `error_message` に日本語で書く。
11. 外部公開を意図する文書（配布物に含まれる `LICENSE`、脆弱性報告窓口の案内等）は、対象読者に応じて英語で書いてよい。この例外は文書単位で判断し、訳文の併置で解決しない。

### 記述の規律

12. 検査手段を持たない規則を文書へ宣言しない。検査できない主張を保証として書かない（ADR-0401 決定3）。
13. 配線されていない道具やコマンドを、存在するものとして記述しない。未配線であることを書く場合は、その旨を明示する。

## 検討した代替案

### 案A: 英語を正本とし、日本語訳を併置する

エージェントと外部読者に対する可読性が高い。ただし ADR 群が日本語である以上、規約から ADR へのすべての参照が言語境界をまたぐ。訳文の同期は機械検証できず、乖離は読者から見えない。

### 案B: 日本語を正本とし、英語訳を併置する

正本の言語は ADR と揃うが、同期の問題は案A と同一で、保守対象が2倍になる点も変わらない。

### 案C: 文書ごとに言語を選ぶ（規約は英語、ADR は日本語）

各文書で最適な言語を選べる。ただし「どちらの言語か」を文書ごとに判断する規則が新たに必要になり、判断の根拠が残らないまま混在が進む。参照のたびに言語が切り替わる点は案A と同じ。

### 評価

| 評価軸 | 案A: 英語正本 + 訳 | 案B: 日本語正本 + 訳 | 案C: 文書ごと | 採用案: 日本語のみ |
| --- | --- | --- | --- | --- |
| Security | 中（訳の乖離が規則の乖離になる） | 中（同左） | 中 | 高（正本が1つ） |
| Testability | 低（同期を機械検証できない） | 低（同左） | 中 | 高（訳文の不在を検査可能） |
| Contract Clarity | 中 | 中 | 低（正が文書ごとに変わる） | 高 |
| Scope Control | 低（文書数が2倍） | 低（同左） | 中 | 高 |
| Cognitive Load | 中（参照ごとに言語が変わる） | 中 | 高 | 低 |
| 対外的な可読性 | 高 | 高 | 中 | 低（意図的） |

## 意図的に捨てるもの

- 日本語を読まない読者が規約本体を読めること
- 英語の規約文書を前提とする外部ツールとの相性
- 訳文による対外的な可読性

## 保証範囲

- 保証すること: 1つの規則に正本が1つ存在すること。正本の言語が日本語であること
- 保証しないこと: 日本語以外の読者に対する可読性。生成区間の内容の正しさ（生成器が保証する）

## 検証方法

- Static Analysis: `*.ja.md` が存在しないこと（決定7）
- Static Analysis: 生成区間のマーカが対で存在し、生成器の出力と一致すること（決定4）
- Static Analysis: 各ユースケースに `README.md` が存在すること（ADR-0102 の検証方法と同一の検査で足りる）
- レビュー: 決定1（再掲の不在）と決定12・13 は機械判定できない。文書を追加・変更する Pull Request のレビュー観点とする

## 影響

- `AGENTS.ja.md` を削除する。エージェントと人間が読む規約は `AGENTS.md` の1本になる。
- 文書を追加するときは、その内容を既存のどの文書も所有していないことを先に確認する。
- `terraform test` のテスト名は英語、その説明は日本語という形になる。

## 見直し条件

- 日本語を読まない開発者が継続的に参加するようになった場合
- 生成区間を持つ文書が増え、マーカの検査だけでは境界を維持できなくなった場合
- 外部公開を意図する文書（決定11）が、例外として扱える数を超えた場合
